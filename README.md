# ScTranslateKit

基于 ParaTranz 协议的桌面翻译工作台。Electron 负责桌面窗口与登录，Nuxt 4 / Vue 负责前端，Rust / Axum / reqwest 负责相应服务。布局参考用户指定的 Transifex 编辑器。

## 启动

关闭现有工作台后双击 `启动.py`，自动将最新修订包同步到统一目录并启动；更新前备份原打包目录。统一启动入口为 `release/desktop/win-unpacked/ScTranslateKit.exe`。旧目录 `release/win-unpacked` 和 `release/verified/win-unpacked` 已改为指向该目录的 Windows 目录联接。`release/window-fix/win-unpacked` 是独立修订构建目录。打包版不需要安装 Node.js 或 Rust；请保留 `win-unpacked` 整个目录。更新版本前先关闭已有工作台窗口。

便携包为 `release/desktop/ScTranslateKit-0.1.0-win-x64.zip`，解压整个包后运行其中的 `ScTranslateKit/ScTranslateKit.exe`。这是未签名的 Windows x64 便携版。

Windows x64 安装程序为 `release/installer/ScTranslateKit-0.1.0-Setup-x64.exe`。运行安装向导可选择安装范围与目录，默认安装到当前用户；提供桌面和开始菜单快捷方式。安装包内置前端、Electron 和 Rust 服务，无需另装 Node.js、Rust 或 Python。构建安装版运行 `npm run package:installer`，输出与便携版分开保存。

启动默认打开项目主页（`/`）。首次未登录显示主页内的启动引导：推荐在应用打开的 ParaTranz 窗口中网页登录，API Token 默认折叠在「备选登录」中。登录先验证账号，无需填写项目链接；成功后在主页选择参与的项目和文件，点击文件进入编辑器（`/editor`）。已有有效登录直接进入主页。未登录时显示登录引导；设置页可重新查看引导。登录窗口使用本应用的独立会话。

记住 Token 是可选项，使用 Electron `safeStorage` 进行系统加密。网页登录支持翻译和实时词条占用；Token 作为备选，可用同一账号的网页登录会话补充占用同步。下一次启动恢复最近明确选择的登录方式，兼容旧版已保存 Token。Windows 数据目录为 `%APPDATA%/sc-translate-kit`（以 Electron `app.getPath('userData')` 为准），其中 `drafts.json` 保存本地草稿，`connection.json` 仅记录登录方式，`app.log` 保存启动日志。日志不记录凭据。

## 已实现

- 启动、登录恢复、项目／文件／词条、建议、术语、历史搜索、草稿、提交与导出统一显示加载反馈。刷新保留内容和滚动位置，加载提示不挤占布局；匹配度与长文本差异在 Web Worker 中计算，关闭目录释放隐藏文件行，长列表使用浏览器内容可见性优化。
- 页面、侧栏、目录、辅助面板、菜单和弹窗使用 M3 Expressive 弹簧动效；空间变化与透明度分别使用官方 Spatial／Effects 参数，并支持系统减少动态效果设置。弹簧曲线由 Motion 在构建准备阶段生成，不增加运行时动画库。修改参数后运行 `node scripts/generate_motion.mjs`。

- 共用侧栏左下角常驻「设置」入口，折叠时显示齿轮图标；打开独立 `/settings` 页面，支持浅色／深色主题、ParaTranz 连接管理和应用版本信息。主题立即应用于所有页面并保存到本设备；进入设置仍先保存草稿，返回保留项目与文件状态。

- 主页与编辑器使用同一个常驻项目／文件侧栏和标题栏；侧栏可展开或折叠，页面切换不会改变宽度。首页负责项目概览与管理，点击文件进入编辑器；删除数字步骤条。返回首页保留当前项目、文件、搜索、目录展开状态和滚动位置；继续翻译保留词条、草稿、编辑列宽、面板与滚动。切换项目返回该项目首页等待选择文件，首次打开项目仅根目录默认展开，其余文件夹默认折叠；搜索展开匹配目录，清除后恢复原状态。刷新复用已有内容，仅显示局部加载提示。管理员仍可修改项目资料、重命名或移动文件。旧 `/projects` 入口重定向到主页。离开编辑器前保存本地草稿，失败时保留当前页面并显示原因。
- 三栏 Flex 布局（默认 47% / 26.5% / 26.5%）可调整宽度，浅色 / 深色模式，文件选择、状态筛选、搜索、分页、本页排序。
- 列表原文与译文等宽并排；中栏按内容高度排列，长原文和译文自然增高，整栏滚动。
- 原文标签和变量高亮，点击插入标记，译文编辑、状态提交、本地草稿恢复。
- 真实 ParaTranz 翻译记忆、术语、历史和评论读取；本地 QA 检查标记、变量、首尾空白。
- 选择词条时自动并行获取本条术语，原文和选中列表行高亮匹配内容；悬停显示译法，点击定位术语卡片。切换辅助标签保留术语，快速换条忽略旧响应，获取失败可重试。
- 保存前读取远端词条并核对原文、译文、状态和更新时间；冲突时拒绝覆盖并保留草稿。
- 可用编辑区宽度 ≤1456px 时切换为列表与编辑器两栏；建议/上下文位于编辑框下方，右侧整体滚动。更宽时恢复三栏。
- 建议面板按当前 Transifex 页面调整：匹配徽标、译文优先、原文差异切换、来源链接；通过筛选的完整原文建议可替换译文。
- 建议栏顶部常驻的历史翻译搜索栏（Ctrl + Shift + F 聚焦）使用 ParaTranz `/api/memory` 接口，支持按文本或键值、原文、译文、键值进行全局历史翻译搜索，不限制为当前项目。输入后按 Enter 搜索，命中词高亮，支持使用译文、清除；清除后恢复自动建议；结果一次显示前 50 条并标明总数。自动建议仍按本地完整原文 Levenshtein 匹配度过滤和排序。词汇索引用于查询项目中的其他原文。
- 差异对比按连续短语合并，在同一段落中显示删除和新增片段，共同文本仅显示一次；空格不作为匹配锚点，标签/变量/换行保持完整。
- 所有自动建议均使用现成 `leven` 库计算完整原文的归一化 Levenshtein 相似度，按本地分数降序显示，过滤低于 70% 的结果。移除自定义加权、锚点、短语窗口和包含关系评分规则；不使用服务器分数参与显示或排序。详见 [算法选型](docs/matching-algorithm.md)。
- 词汇索引与「显示所有出现的情况」按原文查询项目所有文件、所有状态，提供分页、查看原词条和使用译文。
- 建议请求串行执行并缓存 30 秒，不使用 `force` 绕过缓存。
- 提交按钮右侧箭头打开方式菜单，明确选择「保存翻译」「保存并下一条」「保存并标记为有疑问」或「保存并标记为已审核」，在本设备保留选择。保存翻译留在当前词条，即使保存后的状态已不符合列表筛选；保存并下一条在成功后前进，到最后一条时保留当前词条。标记方式在提交时同时保存译文与目标状态，不自动换条，译文未变化时也可仅更新状态；选择菜单选项本身不会提交。保存过程中禁止切换提交方式。
- 译文框将字面 `\n` 显示为实际换行；Enter、粘贴、复制原文、使用建议与插入术语统一处理，草稿及提交自动还原为字面 `\n`，保留连续空行。光标插入按显示文本位置计算。
- 当前页 / 选中词条 JSON 导出，Ctrl+S 保存、Ctrl+Enter / Tab 保存并下一条。

评论编辑通过链接前往 ParaTranz。应用不提供机器翻译、AI 翻译或 Transifex 服务连接。ParaTranz 的项目权限由服务端判断；`403/423/429` 等错误会显示在工作台。

## 开发与构建

需要 Node.js 24.11+、Rust 及 Windows MSVC 工具链。

```text
npm install
npm run dev
npm run typecheck
cargo test --manifest-path service/Cargo.toml
npm run package
python scripts/package_portable.py
```

`npm run dev:web` 仅启动浏览器界面预览。`npm run package` 生成 Nuxt 静态资源和 Rust release 服务，并将它们包含到 Electron 应用中。

## 接口来源与边界

浏览器控制读取了用户指定的 ParaTranz 与 Transifex 页面，并通过该 ParaTranz 标签的网络事件核对路由和响应。接口依据保存于 `docs/paratranz-protocol.md`，官方 OpenAPI 0.5.7 快照保存于 `docs/paratranz-openapi.json`。

应用仅显示登录账号可访问的真实项目数据；未登录或断开连接后清空当前工作区。

版本比较与提交之间仍存在服务端未提供条件写入时的竞争窗口。应用已接入网站的 Socket.IO `/editing` 实时占用协议，显示当前项目的编辑用户和词条占用；最终权限、锁定和提交结果以 ParaTranz 返回值为准。

## QA

QA 面板提供当前词条实时检查和当前文件完整扫描。检查占位符、换行、物品数值与百分比、标签、URL、物品类型及跨词条模板一致性；文件检查纳入本地草稿，计算在 Web Worker 中执行。规则参考 SCCL 的检查代码，结果仅作提示。
